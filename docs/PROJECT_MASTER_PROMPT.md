## 4. Conventions and hard rules

1. **No `Thread.sleep`, no `page.waitForTimeout`.** Use condition-based waits: Playwright auto-waiting/`waitFor`, the `BasePage` helpers (`waitQuietly`, `waitForUrlQuietly`, `waitForUrlChangeQuietly`, `settle`, `waitUntilVisibleAndEnabled`) and `WaitUtils.pollUntil(...)` for backend eventual consistency.
2. **Separation:** page objects hold selectors and actions (no assertions on business outcomes); tests hold assertions (AssertJ). Keep selectors private to the page object.
3. **Login:** use `FurlencoLoginPage.loginAsFreshUser()` (fresh random number + default OTP `test.user.otp`, 1234) for normal tests. Use `loginWithSeed(...)` with a pool from `SeedUsers` only when pre-existing orders/addresses are needed. Returned `LoginTestData` is recorded automatically.
4. **Never hardcode** credentials, phone numbers, emails, OTPs, tokens or URLs in code. Read them from `ConfigManager` (`config/<env>.properties`) or `SeedUsers`. Random data comes from `RandomDataUtils`.
5. **Never commit seed files.** `src/test/resources/seed/*.local.properties` and `*.consumed` are gitignored and secret. Document pool names only, never values.
6. **Mask PII in all output** (logs, Allure, CSV): phone numbers are masked to first 2 + last 2 digits via `LoginTestData.mask`. Never log a full phone number.
7. **A/B experiments:** Furlenco serves different DOM variants. Selectors must tolerate variants; use `FurlencoExperiments` pinning (`furlenco.pin.experiments`) to get deterministic layouts where needed. Prefer role/text selectors over brittle structure.
8. **Retries** go through `RetryTransformer`/`RetryAnalyzer` only.
9. **Traceability:** every test that maps to a sheet row carries `@TmsLink("TC-nnn")`; a test with `enabled = false` is a skeleton with a TODO explaining what is missing.
10. **Groups:** every test has `web` and `furlenco`, plus `smoke` / `regression` / `payment-critical` as fitting.
11. Keep changes small and focused; match the surrounding style; add javadoc whose first sentence summarises a class (it is used in the generated tables).

## 5. How to add things

**Page object:** create `Furlenco<Thing>Page extends BasePage` in `src/test/java/com/tests/pages/furlenco`; constructor takes `Page`; selectors as private constants or lazily built `Locator`s; public methods named for user intent, annotated `@Step`; start with a one-sentence class javadoc.

**Test:** create `Furlenco<Feature>Test extends BaseWebTest` in `src/test/java/com/tests/web/furlenco` with `@Epic`/`@Feature`; each `@Test(groups = {...}, priority = n)` plus `@Severity`, `@Description`, `@TmsLink`. Instantiate page objects from the inherited `page`. Assertions only here.

**Config key:** add the key to every `src/test/resources/config/<env>.properties` (non-sensitive values only; secrets via env vars), read it with `ConfigManager.getInstance().get/getInt(...)` with a sensible default. Keys resolve: `-Dkey` > env var (UPPER_SNAKE) > `<env>.key` > `key`.

**Seed pool:** add a `Pool` enum entry in `SeedUsers`, a placeholder line in `seed-users.example.properties`, and document handling (read-only vs consumed).

## 9. Known gotchas (learned the hard way)

- **Lazy locators:** a `Locator` re-resolves on each use. Reusing one built before a navigation or re-render can point at a different/stale element; re-create it after navigating. Collect product URLs from a listing page before navigating away from it.
- **Signup inputs have no placeholders:** locate them by structure/label/role, not placeholder text. Names must be letters only (no digits) or the form rejects them.
- **OTP auto-submits on the 4th digit:** do not wait for or click a submit button; wait for the outcome (dialog closed, or the new-user signup prompt).
- **OTP and signup lag on staging:** wait with the configured limits (`login.otp.wait.ms`, `login.submit.wait.ms`), never with sleeps.
- **Strict-mode violations:** a selector matching several elements fails. Scope it to a container; use `.first()` only when the first match is intended.
- **A/B variants change markup** (Radix vs MUI dialogs, different headers); never assume one DOM.
- **Wait for Add to Cart to render** before clicking; the button appears after hydration.
- Adding a product to the cart does not by itself prompt login; the prompt appears when paying while logged out.
